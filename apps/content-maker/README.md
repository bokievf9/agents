# content-maker: Контент-мейкер Fir Tech (этап 1, текст)

Голова отдела маркетинга (`../../../COMPANY.md`, план: `../docs/content-plan-2026-12.md`). Каждый понедельник в 09:00
(`TZ`, `PACK_CRON`) готовит пакет недели и присылает владельцу на одобрение. Видео, озвучка и публикация: этап 2.

## Что делает
Пакет недели: 7 сценариев клипов (по одному на день, пн-вс, 20-40 с, хук в первую секунду, сцены с озвучкой и
субтитром, CTA на firtech.pro) и карусель (6-8 слайдов) раз в две недели, плюс подписи и хэштеги для Instagram, TikTok и
Shorts. Темы идут по 8 направлениям услуг (`src/directions.ts`, цены зеркалят `firtech/src/lib/directions.ts`; `site`
не входит) и 6 ракурсам (как работает, цена, было-стало, показ, ошибка клиента, цифра дня): 48 тем. История тем в
SQLite: тема не повторяется 6 недель. Расчёт: 7 клипов + карусель через неделю = 7,5 тем в неделю в среднем, пула 48
хватает на 6,4 недели (за 6 недель уходит 45 тем). Увеличение `CLIPS_PER_WEEK` или `CAROUSELS_PER_WEEK` требует новых
ракурсов или направлений.

Каденс: `CLIPS_PER_WEEK` (1-7, по умолчанию 7) клипов равномерно по дням недели (7 = каждый день). Карусель по правилу
`floor(w*r) > floor((w-1)*r)`, где `w` номер ISO-недели, `r` = `CAROUSELS_PER_WEEK` (0-1, по умолчанию 0.5): при 0.5 это
каждая чётная неделя, при 1 каждая, при 0 никогда. Счётчик не хранится. Карусель ставится в день без клипа (сначала
среда), при 7 клипах в среду рядом с клипом. На стыке 52/53 недель промежуток может быть три недели.

Промпты лежат в `prompts/*.md` (русский, голос бренда). Ответ модели: строгий JSON через `tryJson`, проверка схемой
(zod), затем проверка тона (`src/lint.ts`: обороты «не X, а Y», перечисления отсутствий, стоковые фразы, длинное тире,
эмодзи, обещания цифр, чужие цены, нет firtech.pro). Найденное модель исправляет один раз, остаток уходит владельцу
предупреждением над материалом. Без ключа LLM пакет не создаётся, бот сообщает об этом.

## Команды (только `OWNER_TELEGRAM_ID`, личный чат)
- `/pack`: сгенерировать пакет сейчас (ближайшая неделя с понедельника).
- `/topic <тема>`: один материал; `/topic карусель <тема>`: карусель.
- `/queue`: что одобрено и ждёт выхода. `/stats`: одобрено, отклонено, правки, вторые версии.
- `/skip`: отменить ожидание комментария после отклонения.

## Как работает одобрение
Каждый материал отдельным сообщением «материал N из M» с кнопками Одобрить / Править / Отклонить (очередь одобрений
ядра, тип `content_item`, уровень 0 и `locked`: счётчик доверия не включает автопубликацию). Править: бот спрашивает, какую часть править кнопками (клип: Сценарий / Instagram / TikTok / Shorts; карусель: Слайды /
Instagram), следующее сообщение заменяет только её; маркеры `== Instagram ==` только для показа, бот расставляет их
сам. Одобренный материал сохраняется как `ready`: по строке на платформу (клип: Instagram,
TikTok, Shorts; карусель: Instagram) с типом, текстом и плановой датой (таблица `ready`). Отклонённый: бот просит
комментарий, делает вторую версию один раз с учётом комментария; второй отказ окончательный.

## Переменные
`CONTENT_BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `TZ` (Asia/Tashkent), `DATA_DIR`, `PACK_CRON` (`0 9 * * 1`), `CLIPS_PER_WEEK` (7), `CAROUSELS_PER_WEEK` (0.5), `LLM_BASE_URL`,
`LLM_API_KEY`, `LLM_MODEL_SMART` (`auto`). См. `.env.example`.

## Запуск
`pnpm --filter content-maker dev` (`.env.local`). Docker: `apps/content-maker/Dockerfile`, сервис `content-maker` в
`compose.yaml`, образ `agents-content-maker` в CI, данные `/opt/fir-agents/data/content-maker`.

## Этап 2
Remotion: рендер клипа из сцен (субтитры по строкам), TTS (синтез голоса), Whisper для сверки и тайминга субтитров,
рендер слайдов карусели. Голова Публикатор читает таблицу `ready` и публикует по плановой дате (статус `published`).

# Telegram UX Директора: принятые паттерны

Источники: официальное руководство Telegram (core.telegram.org/bots/features: Menu button, команды и их области,
inline- и reply-клавиатуры, правка сообщений, обязательный ответ на callback, deep links, описания бота) и три бота-образца
админского типа: @BotFather (меню из кнопок, шаги, подтверждения), @ControllerBot (карточка поста с действиями, правка
на месте), бот Trello (карточка задачи с действиями, списки). Ниже структура, которую мы взяли; код в `src/tg.ts`,
`src/director.ts` (`onButton`, `tasksView`, `taskCard`, `deptsView`, `deptCard`, `statusView`), `packages/core`
(`approvals.ts`: `CardFormat`, `settleCard`, `approveAll`; `bot.ts`: `setupBotMenu`, `installApprovals`).

## 1. Меню команд с описаниями (Telegram: commands + scopes, Menu button)
- `setMyCommands` при старте: список владельца в области `chat` (только его личка), общий список пустой (бот чужим не отвечает).
- До 20 команд: сначала ежедневные (start, status, approve, tasks, depts, retry, desk, away), затем справочные, затем
  команды отделов с префиксом отдела в описании («Продажи: КП по лиду»). Остальные команды работают, их список в `/help`.
- Кнопка меню = список команд (`setChatMenuButton` type `commands`). `setMyDescription` (≤ 512) и `setMyShortDescription` (≤ 120).
- Ошибка любого шага только в лог, бот стартует.
- Боты отделов сообщений не читают (только постят в темы группы), поэтому у них нет команд: описание говорит, что
  команды у Директора. Так меню никогда не обещает того, что не работает.

## 2. Постоянная reply-клавиатура для навигации верхнего уровня (BotFather, Telegram reply keyboards)
- Пять кнопок под полем ввода: `📥 Одобрения · 📋 Задачи · 📊 Статус` / `🏢 Отделы · 🆘 Помощь`, `is_persistent`, `resize`,
  подсказка в поле ввода. Показывается на `/start`, `/help` и подсказке на непонятный ввод, Telegram её сохраняет.
- Нажатие = текст кнопки = та же команда (`menuCommand`). Текст кнопки никогда не принимается за правку предложения.

## 3. Карточка-объект с действиями прямо под ней (ControllerBot, Trello)
- Каждое предложение на одобрение отдельным сообщением: жирный заголовок «#id · отдел · вид», служебная строка курсивом
  (номер в пачке, задача, тип, уровень доверия, 🔒 для денег), суть, превью текста ≤ 500 знаков в цитате.
- Ряд решений `✅ Одобрить · ✏️ Править · ❌ Отклонить`; второй ряд: части для правки (если их несколько) и `👁 Полностью`.
- Карточка задачи: статус словами, исполнитель, строка хода, последнее событие; кнопки зависят от статуса
  (`🔁 Повторить` только у застрявшей, `❌ Отклонить` только у открытой).

## 4. Результат действия правит то же сообщение (Telegram: editing, ControllerBot)
- После решения карточка редактируется на месте: `✅ Одобрено · заголовок`, `❌ Отклонено`, `✏️ Правка принята, одобрите`
  (новая карточка ниже). Кнопок решения после этого нет, повторное нажатие старой кнопки невозможно.
- «Править»: карточка становится `✏️ Жду правку` с кнопками `Одобрить как есть / Отклонить`, чтобы из ожидания был выход.
- Решение на сайте /admin тоже правит карточку в Telegram, если она туда дошла.

## 5. Навигация внутри одного сообщения (Trello lists, Telegram pagination)
- `/tasks`: 10 задач на страницу, `◀ n/N ▶` и фильтры отделов сверху правят то же сообщение; кнопка `#id` открывает
  карточку задачи там же, `◀ Назад` возвращает на ту же страницу того же фильтра.
- `/status` → кнопка отдела → задачи отдела; `🏢 Отделы` → карточка отдела → `⏸ Пауза / ▶ Возобновить`, `📋 Задачи`, `◀ Отделы`.

## 6. Подтверждение необратимого (BotFather: «Are you sure?»)
- Отклонение задачи спрашивает `❌ Да, отклонить / ◀ Нет` в той же карточке; пауза отдела обратима и не спрашивает.
- Пакетное действие (`✅ Одобрить все обычные`) никогда не трогает цены, деньги и карточки со своими кнопками: они по одной.

## 7. Пачка с заголовком и массовым действием (ControllerBot: очередь постов)
- Перед карточками заголовок «Пачка на одобрение: N предложений» с `✅ Одобрить все обычные` и `⏭ Позже`, если обычных
  хотя бы два. После нажатия заголовок правится в итог (одобрено, не выполнено, осталось по одной).
- Каждое массовое одобрение идёт через обычный `handle`, поэтому счётчик доверия и журнал как при нажатии по одной.

## 8. Каждая кнопка отвечает, старые кнопки говорят «Устарело» (Telegram: answerCallbackQuery)
- Любой callback получает `answerCallbackQuery` с короткой подсказкой («Одобрено», «Стр. 2 из 3»), даже если обработчик упал.
- Данные кнопок с пространством имён и ≤ 64 байт: `ap:` одобрения, `tk:` задача, `pg:` страница списка, `dp:` отделы
  (`ce:`, `rl:`, `pb:`, `pc:` прежние кнопок голов). Неизвестная или старая кнопка: «Устарело», ничего не меняется.

## 9. Единый стиль сообщений
- HTML во всём, что пишет Директор; всё не-разметочное экранируется (заголовки задач, тексты клиентов).
- Жирный заголовок, одна эмодзи на действие или раздел, номера и суммы моноширинным, курсив для служебного.
- Без стен текста: список задач по страницам, журнал задачи только 8 последних записей, длинный текст карточки по кнопке.
- В «входящие» сайта и в ответы сайту уходит тот же текст без разметки.

## 10. Никогда не молчать (BotFather)
- Непонятный текст или неизвестная команда: короткая подсказка с клавиатурой. Модель недоступна: то же, плюс причина.

# Prospector: Разведчик (этап 1)

Агент отдела продаж. Готовит владельцу первые сообщения бизнесам Центральной Азии, отправляет их владелец сам.
Отдельный бот (`PROSPECTOR_BOT_TOKEN`), отвечает только `OWNER_TELEGRAM_ID`, остальных молча игнорирует.
Правила компании (`../../../COMPANY.md`): цены и деньги всегда уровень 0, первые ответы уровень 1; здесь на этапе 1
**всё** уходит через владельца: агент ничего никому не пишет.

## Запуск
```
cp apps/prospector/.env.example apps/prospector/.env.local
pnpm --filter prospector run import ../../../docs/prospects-2026-11.csv   # загрузка базы (повторный запуск безопасен)
pnpm --filter prospector dev
```
Загрузка называется `import`, но у pnpm есть встроенная команда `pnpm import`, поэтому нужно писать `run import`.
Дедупликация по «название + город», статус новых строк `new`. База: SQLite `prospector.db` в `DATA_DIR`.
Без ключа LLM работает «LLM off»: черновики из шаблона (зацепка из CSV + цена), всё остальное то же.

## Как работает
1. **Пакет в 10:00** (`BATCH_CRON`, часовой пояс `TZ`, по умолчанию Asia/Tashkent; `BATCH_SIZE`=10). Сначала дожимы,
   потом новые бизнесы по приоритету ниш из COMPANY.md: учебные центры и репетиторы, магазины, салоны/барбершопы/стоматологии,
   доставка и кафе, затем резерв.
2. **Карточка** на каждого: название, город, ниша, контакты как в CSV (Telegram, Instagram, телефон, сайт), предложение с
   ценой, черновик. Кнопки: «Скопировать» (присылает голый текст отдельным сообщением, чтобы скопировать долгим нажатием),
   «Править» (следующее сообщение заменяет черновик), «Пропустить», «Отправлено» (статус `sent` и дата).
3. **Черновик**: RU, 2-4 предложения, одна зацепка из строки, одно предложение с ценой из `directions.ts` (копия в
   `src/offers.ts`: бот-администратор от $250, ИИ-приёмщик от $300, Mini App от $500), один вопрос. Модель отвечает строгим JSON,
   разбор терпимый; ответ проверяется (цена ровно как дана, один вопрос, нет других сумм, нет длинных тире), иначе шаблон.
   Промпты: `prompts/*.md`.
4. **Дожимы**: через 3 и 7 дней после `sent`, если ответа нет, агент предлагает короткое напоминание (карточка с теми же
   кнопками). Через 10 дней после отправки без ответа статус `no_reply`.
5. **Ответ бизнеса**: `/reply <id>` ставит `replied` и просит переслать текст ответа. Дальше черновик ответа с двумя слотами
   звонка (11:00 и 15:00 по Ташкенту). Цены модель не называет: ставит `[цена]` / `[срок]`, пока метка в тексте, «Отправлено»
   не нажимается, владелец подставляет цифры через «Править».

Статусы: `new → proposed → sent → replied / no_reply / skipped` (`no_reply → replied` при позднем ответе).

## Команды (только владелец)
`/batch` пакет сейчас, `/next` ещё одна карточка, `/stats` воронка по статусам и нишам, `/find <текст>` поиск по названию,
городу, нише, номеру, `/reply <id>` бизнес ответил.

## Переменные окружения
`PROSPECTOR_BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `DATA_DIR`, `TZ`, `BATCH_CRON`, `BATCH_SIZE`; LLM: `LLM_BASE_URL`, `LLM_API_KEY`,
`LLM_MODEL_SMART` (по умолчанию `auto`), `ANTHROPIC_API_KEY`, `LLM_TIMEOUT_MS`, `LLM_MAX_RETRIES`. Пример: `.env.example`.

## Почему отправка ручная
- Telegram-бот не может написать пользователю первым: только тому, кто сам нажал /start у бота.
- Автоматизация личного аккаунта через MTProto (Telethon, gramjs) нарушает правила Telegram, холодные рассылки быстро
  ловят спам-блок и бан, и рискуем личным аккаунтом владельца. Instagram автоматизацию директа блокирует так же.
- Поэтому: агент находит, пишет и напоминает, человек нажимает «отправить».

## Этап 2 (варианты)
1. Отдельный аккаунт-«визитка» студии и MTProto с лимитами (до 10-15 первых сообщений в день, паузы, прогрев): риск бана
   принимается на тот аккаунт, не на личный.
2. WhatsApp Business API с шаблонами: официальный путь, платный, нужна верификация.
3. Партнёрские каналы: комментарии и посты в локальных чатах бизнеса, реклама на Telegram Ads с лидформой.
4. Мини-панель в HQ: карточки с кнопкой «открыть чат» (`t.me/<ник>`, `wa.me/<номер>` с готовым текстом), без автоотправки.

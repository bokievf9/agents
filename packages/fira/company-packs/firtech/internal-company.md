# Fir Tech: компания из ИИ-агентов

Версия 1, 2026-11-18. Владелец решает продукт, деньги и право. Всё остальное делают агенты.
Документ ведёт главное окно; изменения отделов и должностей согласуются с владельцем.

## Принципы
- **Два вида сотрудников.** Строители: сессии Claude Code, они пишут код, сайты, агентов (работают,
  когда их запускают). Исполнители: автономные агенты на сервере, работают 24/7 по расписанию и по
  событиям (Dono первый). Строители создают исполнителей.
- **Один шаблон.** Каждый исполнитель это копия шаблона Dono: Node + TypeScript, Telegram, SQLite,
  расписание, Claude API, свой контейнер без прав. Новый агент это новая «голова» на том же теле.
- **Уровни доверия.** Уровень 0: агент только предлагает, владелец нажимает кнопку. Уровень 1: агент
  делает сам, отчитывается. Повышение после 20 одобрений подряд без правок. Деньги, договоры и
  цены всегда уровень 0. Дежурный первый ответ клиенту и уточняющие вопросы на уровне 1
  (решение владельца 2026-11-18); слоты звонка по умолчанию ближайшие два рабочих дня в 11:00 и
  15:00 по Ташкенту.
- **Офис в Telegram.** Группа «Fir Tech HQ» с темами по отделам. Приказы владельца и отчёты агентов
  живут там. Кнопки «одобрить / править / отклонить» под каждым предложением.
- **Один сервер, изоляция по пользователям и контейнерам.** Один поток разработки за раз.
- **Модель по сложности.** Haiku: разметка, извлечение, проверки. Sonnet: тексты, код, диалоги.
  Opus: архитектура, безопасность, ревью. Бюджет API ведёт Финансист.
- **LLM для исполнителей через OmniRoute** (решение владельца 2026-11-18): локальный шлюз к
  бесплатным провайдерам с Anthropic-совместимым `/v1/messages`; агенты получают `LLM_BASE_URL`
  и `LLM_API_KEY`, модель `auto` или `provider/model`. На сервере OmniRoute это отдельный
  контейнер во внутренней сети. Ограничение: через бесплатные провайдеры нельзя гонять данные
  клиентов и код клиентов (их условия и приватность); для клиентских задач платный ключ позже.

## Что продаём (витрина firtech.pro, все 8 направлений)
Маркетинг бьёт в первые пять, остальные есть в прайсе и продаются по входящим.
1. Бот-администратор для услуг (запись, напоминания, отзывы).
2. ИИ-приёмщик заявок в Telegram, WhatsApp, Instagram, 24/7.
3. Автоматизация рутины: Google Sheets, CRM, мессенджеры, отчёты, рассылки.
4. Контент на автопилоте по подписке: посты, карточки, ролики.
5. Telegram Mini Apps: магазины, записи, лояльность.
6. Личные агенты по образу Dono (студенты, фрилансеры, владельцы).
7. Внедрение ИИ в компанию: базы знаний, ответы по документам, обучение команды.
8. Обучение: как внедрить агентов в свой бизнес.
Сайты и лендинги остаются в прайсе как основа для всего выше.

## Решения владельца 2026-11-18
- Структура и должности утверждены. Цены только в долларах, ниже рынка; деньги не главное,
  главное клиенты и кейсы.
- Старт: Центральная Азия (Ташкент, Алматы, Душанбе, Бишкек), русскоязычный контент.
- Ниши для Разведчика по спросу: (1) учебные центры и репетиторы (языки, подготовка к экзаменам,
  IT-курсы), (2) магазины в Instagram и Telegram, (3) салоны красоты, барбершопы и стоматологии,
  (4) доставка еды и кафе. Резерв: автосервисы, фитнес, турагентства, недвижимость.
- Оплата клиентов: картой или по счёту после регистрации юрлица, по этапам проекта (решение владельца 2026-11-24:
  криптовалюты нет вообще; до юрлица продажи ждут, провайдер эквайринга выбирается по стране юрлица); Биллинг это учитывает.
- Добавлено по рекомендации: Реферал (клиент приводит клиента, скидка на сопровождение) в отделе
  продаж; Онбординг клиента (доступы, инструкция, первая неделя) в сопровождении.

## Решения владельца 2026-11-19
- Dono: учебные блоки только в учебные дни семестра по готовому календарю занятий владельца;
  в остальные дни только горящие дедлайны и воскресный разбор.
- Часовой пояс личных агентов (Dono, Polly): Asia/Kuala_Lumpur. Клиентские слоты Приёмщика
  остаются по Ташкенту.
- Каналы контента: Instagram `firtech.pro` (есть), TikTok `firtech.pro` (создать с тем же именем),
  YouTube Shorts те же клипы. Telegram-канала на старте нет: Telegram используется как канал
  продаж (бот сайта, личные сообщения Разведчика, Mini App для клиентов), а не как медиа.
- Dono и Polly показываются в контенте как готовые продукты Fir Tech («личный ассистент
  студента», «учитель языка»), с размытыми личными данными; им нужна карточка и цена на сайте.
- Боты: @firtech_leads_bot (Приёмщик), @polly_firtech_bot (Polly), @dono_firtech_bot (Dono).
- Архитектура HQ (решение 2026-11-19, техзадание `docs/architecture-hq.md`): не бот на агента, а
  бот на отдел с головой-руководителем; над головами Директор (один бот `Fir Tech HQ`), владелец
  общается только с ним; голова пишет сама только утреннюю сводку, пачку на одобрение и алерты;
  исполнители это модули без своих ботов; все отделы в одном процессе `apps/hq`; у Paperclip
  берём идеи (задачи-тикеты, heartbeat, оргчарт, бюджеты, рутины, журнал), не продукт.
  Главное окно Claude Code остаётся директором по стройке: Директор на сервере ставит задачу
  «нужен строитель», владелец передаёт её главному окну.

## Решения владельца 2026-11-19, вечер
- **Сложные задачи делают строители**, а не бесплатные модели: клипы (Remotion), новые функции,
  правки кода и правил. Агент ставит задачу с меткой `builder`, Директор создаёт issue в приватном
  репо `bokievf9/agents` (fine-grained токен, только Issues); главное окно Claude Code разбирает
  такие issue при каждом выходе на связь и по слову владельца «смотри задачи», закрытие issue
  двигает задачу в HQ дальше. Следующий шаг: плановый облачный агент Claude Code разбирает issue сам.
- **Должности на английском**: Director, Head of Marketing, Trend Scout, Content Maker, Publisher,
  SEO Specialist, Analyst, Head of Sales, Lead Handler, Prospector, Presales, Referral, Head of
  Support, Monitoring, Finance, Customer Support, Onboarding, Head of Production, Project Manager,
  Head of Back Office, Documents, Billing. Описания и общение на русском.
- **Бюджета на API нет**: всегда лучший бесплатный вариант (YouTube Data API, Google Trends RSS,
  Search Console, Метрика, OmniRoute с бесплатными провайдерами); платное только по явному
  решению владельца.
- **Порядок стройки**: отдел целиком, затем следующий (Marketing → Sales → Support → Production и
  Back Office), в конце «живой офис» в админке firtech.pro.

## Где живёт код
- `firtech/`: сайт firtech.pro (витрина, прайс, кейсы, лиды).
- `agents/`: монорепо исполнителей Fir Tech. `packages/core` общее тело (Telegram, база,
  расписание, Claude, одобрения), `apps/<агент>` головы. Один CI, один образ на агента.
- `dono/`, `polly/`: личные агенты, отдельные репо, тот же шаблон. Когда ядро `agents/core`
  устоится, Dono переезжает на него.

## Фазы
- **Фаза 0, без сервера (сейчас).** Этот документ. Репо `agents/` с ядром из Dono. Приёмщик лидов
  и Контент-мейкер работают локально. Новая витрина firtech.pro с 8 направлениями и Dono как
  кейсом. Контент-план на месяц. Разведчик собирает базу первых 100 бизнесов.
- **Фаза 1, сервер.** Сайт, Приёмщик, Публикатор и Мониторинг в прод. Группа HQ.
- **Фаза 2.** Разведчик, SEO, Аналитик, Пресейл. Первые платные клиенты через агентов.
- **Фаза 3.** Менеджер проектов, Саппорт, Биллинг, Финансист. Бот-администратор как коробка.

расход на API и серверы, число агентов на уровне доверия 1.

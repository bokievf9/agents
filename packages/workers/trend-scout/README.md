# @fir/worker-trend-scout: Трендвотчер (этап 1)

Исполнитель отдела маркетинга. Только читает публичные сигналы и пишет в таблицы `ts_*` общей БД HQ; наружу ничего не
публикует. Голова маркетинга запускает его рутинами `marketing-trends-daily` (каждый день 08:30 по Ташкенту) и
`marketing-trends-weekly` (воскресенье 20:00, итог недели попадёт в сводку понедельника).

## Что делает
- `action: trends`: собирает сигналы, просит модель (strict JSON через шлюз) выбрать до 5 самых полезных и сформулировать
  для каждого: хук (своими словами), формат ролика, почему растёт, ссылка на источник, направление из 8 услуг.
  Результат в `ts_items` (день, место, хук, формат, почему, источник, ссылка, направление). Повторный запуск в тот же день
  ничего не пересобирает (`meta.force` пересобирает).
- `action: trends_weekly`: сводка в 3-5 строк по сохранённым за неделю элементам.
- Контент-мейкер получает свежие тренды через параметр `trends` (`ContentMakerWorker({ trends })`, по умолчанию их нет):
  голова передаёт `latestTrendHints`, максимум два тренда на материал, приоритет у тренда с тем же направлением.
  В промпт идёт правило «вдохновение, не копируй чужие тексты, источники не называй».

## Источники (каждый включается своим ключом или настройкой)
| Источник | Включается | Что берём |
|---|---|---|
| Google Trends, дневной RSS `https://trends.google.com/trending/rss?geo=KZ` | `TRENDS_REGIONS` (по умолчанию `KZ,UZ,RU`, пусто: выключено); ключ не нужен | популярные запросы региона и ссылка на новость |
| YouTube Data API v3 | `YOUTUBE_API_KEY` | `videos.list chart=mostPopular` по регионам (1 единица квоты) и `search.list` по 6 нишевым запросам на русском, `order=viewCount`, `publishedAfter` 7 дней (100 единиц каждый, около 700 из 10 000 бесплатных в сутки) |
| TikTok Creative Center | не используется | публичного JSON без входа в аккаунт нет, скрапинг с логином нарушает правила площадки |

Reddit и Telegram не используются. Ошибка одного источника не роняет запуск: она попадает в заметки результата, ключ в
текст ошибок не попадает.

## Подключить YouTube
1. console.cloud.google.com, создать проект, «APIs & Services», «Enable APIs», включить YouTube Data API v3.
2. «Credentials», «Create credentials», «API key». Ограничить ключ по API (только YouTube Data API v3).
3. Положить в `/opt/fir-agents/.env` как `YOUTUBE_API_KEY=...`.

Тесты: `pnpm --filter @fir/worker-trend-scout test` (fetch и время подменены, сеть не нужна).
